## 3. Engineering Analysis & Big Data Principles

1. **Partition Pruning Mechanism**:
   When queries specify `city` and `date`, the Hive Semantic Analyzer directly prunes HDFS directory paths at compile time via the Hive Metastore catalog. The MapReduce `FileInputFormat` strictly constructs splits for matching partition subdirectories rather than traversing the entire HDFS directory tree.

2. **Network and Disk I/O Minimization**:
   In enterprise production clusters, analytical jobs frequently query specific operational dates or regional hubs. Without partitioning, every daily dashboard refresh triggers multi-terabyte network shuffles across cluster racks. By partitioning across `(city, date)`, network saturation and disk seek times are reduced by two orders of magnitude.

3. **Storage Overhead Tradeoff**:
   Small partitions introduce additional HDFS NameNode metadata inode footprint. To optimize this tradeoff, partitioning was applied hierarchically at coarse granularity (City $\rightarrow$ Date) rather than per-hour, preventing the HDFS Small Files Anti-Pattern.
